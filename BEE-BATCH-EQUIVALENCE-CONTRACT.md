# Route Bee publication equivalence

Route spatial-stop-v2 retains one immutable server batch per client callback and its original serialized witness. It does not pin a batch across action ticks. The final native fence permits a replacement publication only when a bounded, synchronized comparison of immutable values proves the same context, server-level identity, dimension, complete valid coverage, and identical semantic records for every captured live Bee. Source tick and monotonic nanoseconds alone may advance; both old and latest evidence must remain within the existing 250 ms / five-tick limits.

Anger, target, alive/class/identity, sting, nectar, hive, flower, read-status, missing rows, incomplete coverage, backwards clocks, expiry, or context replacement refuse. No engine getter or external callback runs under the store monitor. Existing raw client identity/geometry/projection, terrain, owner and release fences remain authoritative. The comparison is a read-only linearization point, not a guarantee that future AI publications cannot change. A later callback acquires its own fresh batch.

Public success profile, policy, schema and original witness are unchanged. The existing bounded schema-2 refusal diagnostic and known/unknown settlement rules remain unchanged. No action retry, reacquisition, resume, defense or broader entity permission is introduced.

# Recovery closure: first offline test candidate

This source tree is an integration candidate for an independent, explicitly labeled TEST ONLY singleplayer world. It is not a completed live release. Deploy only a final source/JAR pair whose hashes appear in the integration artifact manifest. Preserve the original world and existing paused task records. No unknown action may be replayed, resumed automatically, or replaced with a new identity.

## Intended first acceptance scope

- Durable observation jobs, exact owner cleanup and request identities, original freshness checks, complete error envelopes, and bounded Node reply draining.
- Explicit `clear_hand` and state-bound `recover_cursor`, using ordinary vanilla inventory clicks, aggregate capacity/budget admission, complete item conservation and required native click/send fences.
- Conservative native no-effect provenance, owner-bound placement outcome verification, and immutable bounded diagnostic retention.
- A standalone public fall-rescue guard under one existing owner chain, with an explicit bounded authorization window and separately reported physical outcome and release.
- Read-only supported external-controller idle evidence and ordinary-action handoff fences.
- Opt-in bounded compact observations with explicit incomplete coverage and no execution authority.

Use the public catalog's negotiated availability and exact argument contracts. One existing `request_only` Watchdog can support both inventory recovery and the standalone fall guard when the submitted execution policy matches it. No second writer or parallel guard job is allowed.

## Still pending beyond this first artifact

Attached fall protection inside an ordinary movement/combat job; managed external-controller stop/route jobs; broader hazard reflexes and combat behavior; new public bed, torch and portal workflows; armor unequip and production-menu cursor recovery. Existing source-only catalog entries are not newly enabled by this batch. First-artifact tests do not establish any of these pending capabilities.

## Evidence boundaries

Offline compilation, exact Java wire validation, actual registered-mixin bytecode transformation, and synthetic public owner-chain tests are separate from live game behavior. Cooperative native capture budgets are rejection limits, not hard real-time guarantees. A placement or inventory success remains client-observed unless an explicit stronger evidence field says otherwise. Correlated integrated-server fall observations are reported separately and do not promise future survival or packet acknowledgement.

The final operator handoff names the exact version, source inventory, JAR hash, validation receipts, and supported same-desktop-namespace launch recipe. Preparation alone is not an install-ready signal.

# 退避逐窗口一致性候选

版本：`1.1.7-integrated.retreat.1`，基于 `1.1.7-integrated.1`。
状态：隔离离线候选；本候选 **0 次实机执行**，未安装、未重启、未部署。历史集成或旧版本实测不构成本候选验收。

## 修复了什么

旧实现规划 3 格退路时使用两个 1.5 格段，每段要求最近威胁净空增至少 0.1；执行却使用 0.65 格窗，仍要求至少 0.1。因此同一静止快照下，横移长段可通过而首个执行窗被拒绝。保存的 tick9 几何能精确复现 0.049138781384 的首窗增量；tick10 对应 0.053934159633。

现在规划与执行都经过同一个生产组合 `CombatRetreatWindow.check`：

1. 从起点按 0.65 格窗逐段验证，到实际到达容差 0.25 内停止。需要发出的较短末窗仍要求完整 0.1 改善，不按比例降低阈值。
2. 每个窗使用当前威胁快照；逐威胁整段净空不得降低，最近威胁及整体最小净空都须改善至少 0.1。保留既有 1e-7 浮点容差。
3. 同一个 helper 检查 12 格动作区域、动态实体、已加载平地/支撑和保守运动包络。短末窗也保留沿同方向至少 0.65 格的完整空间前视，包含终点外延；减小输入不被误当作能消除惯性。
4. 优先检验远离当前最近威胁的方向，然后按正负角度交替最多 16 个方向。使用首条全部通过的候选；每次规划总预算 8ms，每条最多 7 窗。预算到达/倒退会拒绝本次候选，完整记录预算耗尽、候选/窗口数与拒绝原因，不能把未搜完说成确定无路。
5. 真正执行前，每 tick 从玩家实际位置重新验证所有剩余窗口，使用新威胁快照、新动态碰撞与新地形缓存。规划通过不豁免执行。

原精确横向反例现在在规划第一窗就被拒绝，不会作为可执行计划下发。空地直接远离路线通过生产 helper 的离线组合测试。后者不证明真实世界中相应方向存在通路。

## 持续安全边界

- 任意危险实体新增、消失、死亡、ID/UUID/类型改变，拒绝继续；不会把未观察到敌人当作已脱险。
- 相邻有效观察间任意敌人的实际净空下降，立即拒绝。移动威胁即使未导致实际净空下降，也必须通过本 tick 全部剩余窗口的重算。此候选没有无界重规划或安全锁存恢复。
- 每最多 10 tick 或 500ms（先到者），玩家沿目标方向的实际位移与整体最小威胁净空必须各增加至少 0.1；否则终止。敌人自己远离不能替代玩家移动，多敌“最近者”切换不能借用旧最近敌的改善。
- 原动作时限、60 tick / 3 秒 / 4 格退避预算、运动姿态/速度检查、人工接管/取消/终止输入释放仍有效。规划等待、检查失败、时限到达均返回零前进输入。
- 所有退避阶段始终 `risk_remaining=true`、`safety_assured=false`。走完一段仍是 `failed / retreat_segment_completed_risk_remaining`；不会被说成击杀成功或脱离爆炸危险。近苦力怕横向小幅增距不构成脱险证据。

安全策略比旧实现更保守。正在逼近的敌人、短末段、最近威胁切换、真实客户端耗时或运动残余可能使候选更早终止；本候选没有承诺消除所有中断，也没有放宽危险门槛。

## 健康观测诊断

健康策略数值与优先级保持：150_000_000ns 间隔硬限（严格大于才拒绝）、最大 tick 跨度 3、同 tick 累计停留 150ms、低血 14HP、1 秒累计掉血 4HP、动作内不可逆锁存。增加以下证据，既有 Result/health 字段语义不变：

- `threat_gate.health_diagnostics.current_observation`：本次健康采样 tick/ns/健康值、上一有效诊断样本 tick/ns、精确 `sample_delta_ns` / `tick_delta` / `same_tick_elapsed_ns`。
- `latch_trigger`：永久保留首次中断的上述观测、原因、健康已知性与窗口损失。之后当前样本继续更新，但不会恢复攻击或抹去中断。
- 独立 `wall_gap`、`tick_gap`、`frozen_tick` 与可组合 detail；阈值、比较符、是否本次触发锁存、是否实际执行安全策略均可见。
- “上一有效诊断样本”指有限非负健康、非负且单调 tick/ns 的上一观察，包含发生 gap 的样本；无效健康或倒退时钟不会推进诊断参考。它不是安全连续性恢复证明。

这些数据只描述本地客户端健康观察。没有网络丢包、掉血来源或服务端失联归因；旧实测没有的 tick8→9 精确间隔也没有被伪造。本次 150ms 边界数据来自合成离线测试。

# Later live acceptance, only after the separate dragon trial

No item below was run by this candidate. A check mark requires retained evidence for the exact installed artifact; a build or offline fixture is not a live pass.

## Before enabling any candidate

- Verify operator authorization, disposable/isolated test world, unique candidate version/hash, exactly one controller and ordinary API cancel/release. Preserve the existing live `.5` and backups. No installation is implied by this checklist.
- Complete and review the separately authorized dragon test first. Review the merged boat/detour/expedition code and rerun its full offline suite before installing anything.
- Start on supported low-risk ground with no inventory at risk. Record client/action session, world generation, actor UUID, navigation epoch, pose, velocity, support and loaded status.

## Native discontinuity guard

- While a bounded ordinary path is active, exercise a controlled same-dimension large position change: action terminal `position_discontinuity_rebind_required`, owner released, held inputs empty, no further old-path advance.
- Repeat while idle and between two queued paths. The second old path must be refused without movement even though player and level objects/dimension are unchanged.
- Queue a path before the move that already contains the previous epoch/origin; reject it. Repeating the same action ID returns its old outcome; it does not replay.
- Three reads in one tick must not establish stability. Unloaded footprint, unsupported feet, airborne gateway exit, high velocity and mount must prevent walking rebinding.
- On freshly observed supported ground, wait three distinct stable ticks, discard the old cursor/path, plan a new route, bind the new epoch and origin. A stale origin >0.25 blocks away must fail.
- Walk, sprint, jump, take normal knockback and ordinary small server corrections: no false large-displacement cancellation. Unusually large correction may intentionally cancel; record actual telemetry rather than lower thresholds blindly.
- Verify <16-block teleport limitation explicitly and do not call the guard a universal teleport detector.
- Verify GUI, cancel, API direct takeover, death, disconnect and player/level replacement cleanup; physical keyboard takeover is a separate unsatisfied requirement.
- Boat integration: steering not cancelled just because walking rebind support/low-speed conditions fail. After dismount/large relocation, a fresh walking route still needs its own observed binding.

## End gateway, only with a separately completed safe-use adapter

- Candidate 1 cannot launch a pearl. Do not substitute raw use keys or a fake verified proof to finish this checklist.
- First cancel the old path and confirm release before entering the gateway. Verify loaded frame/trajectory, exact pearl count/slot and the entire safe possible landing region.
- Dispatch at most once. Preserve the same action ID on response loss and observe; do not resend with a new ID.
- Record actual post-gateway player pose/velocity/ground/support/loading. The projectile exit point is not the player's verified landing point.
- Reobserve and replan after arrival; old same-dimension routes remain invalid. If any landing region/trajectory is unknown, abort the crossing.

## Shulker foundation

- In an isolated safe room, verify all 27 menu slots and exact menu identity/position before transfer. Use plain expendable cargo only.
- Recipe: two actually observed shells plus one chest, shell/chest/shell vertical in the 3x3 grid; verify output and exact deltas, empty cursor/grid. 2x2, wrong ingredient and uncertain result stop.
- Snapshot: normal box contents, dyed boxes, >4 boxes, renamed/styled items, enchanted/custom-component cargo and oversized/malformed data. Truncated/incomplete identity must block exact lifecycle verification and not overflow JSON.
- Future adapter: place → open → load/unload with actual conservation → close → break → observe exactly one matching recovered box → replace/reopen → compare all contents. Break without pickup is not success. Same-looking duplicate boxes are ambiguous and require explicit resolution.
- Interference, cursor carry, GUI change, changed source slot, timeout/disconnect or unknown action result must halt without cleanup clicks/replay. Final close/recovery after inspection is separately controlled.

## Authority and protocol

`recovery_maintenance_v5` is selected by an explicit startup flag and explicit request profile, over the existing interaction/v3 route. No new HTTP service or credential. Original owner, all 101 historical records, same global single in-flight ID, durable dispatch fence, absolute submit TTL, exact stop/queued invalidation, input release and sticky UNKNOWN are retained. Movement uses the existing at-most-eight-sample first-sample jump executor; ordinary breaks at most 32 calls / 2000 ms; TNT removal and placement each at most one vanilla call. Look/select remain one-shot. A completed attempt is not a guarantee that a block broke, a block was placed, or a landing succeeded. Ordinary damage, missed/blocked placement, incomplete mining and landing short are gameplay outcomes, not automatically protocol UNKNOWN. Entered-call exceptions or unresolved dispatch/release authority retain UNKNOWN and the original ID.

PLAN3 is local, read-only, raw-hash and current session/world_generation/player/owner bound. Within the same session/world/player, each exact break/restore target has at most one deliberate maintenance intent across PLAN changes; even known-zero consumes it. No automatic target replacement or retry. The total task catalogue is stable TNT (at most nine), cut_sandstone and the two reviewed chiseled_sandstone service cells (at most thirteen service cells), plus at most thirteen andesite restoration cells. Native does not embed absolute map coordinates: it enforces the request's exact position, face, identity, current state, permitted fixed block/item classes, ray/reach, full selected stack, owner and world context. The public layer preserves the full reviewed PLAN proof and matches the exact task entry before durable intent. Old v1/v2/v3/v4 policies are not widened.

## Break and restore

- `break_service`: only the PLAN's cut_sandstone/chiseled_sandstone blocks, exact ordinary native Block instances, dry state and no block entity. Never remove a block intersecting the current player body or the column beneath the current footprint/support.
- `break_tnt`: exact native TNT, current `unstable=false`, current local no-neighbor-signal and no adjacent fire/soul-fire/lava facts, loaded bounded neighbors, actual target ray and stone pickaxe slot 2 full-stack binding. Normal TNT is instant-break, so one call only. Cold state is planning evidence, not fresh authorization or a future no-ignition guarantee.
- `restore`: only MAIN_HAND, exact native andesite BlockItem from slot 3, exact full stack. Destination must be the PLAN's current air cell, outside player body, adjacent to the exact designated anchor/face/hit point. Anchors are only exact ordinary stone/sandstone/cut_sandstone/chiseled_sandstone/andesite blocks listed in the PLAN; no container, bed, TNT or interactive block.
- Restore invokes the existing vanilla `MultiPlayerGameMode.useItemOn` once. Durable fence precedes the call, because local prediction and event callbacks occur before its packet. A narrow captured-call/packet witness uses existing relevant hooks, not a global block-writer proof. No use key, offhand fallback, repeated right click, self-made place packet, direct block/HP/velocity edits, item spawning, creative or gamerule edits.

Only the actual ray target needs additional TNT properties and six-neighbor current facts; a bounded `ray_target_witness` may cover a normally reachable target outside the 150-cell local window. It must match the captured actual ray, not be fabricated from PLAN coordinates. Missing/unloaded facts prevent ticket publication. Existing 64 KiB response bound and local shape/step-height/sprint facts remain. Local observations are conditional current facts, not global ecological or future-effect guarantees.

A fixed local player-centered AABB (eight blocks on each axis) reports a bounded PrimedTnt count plus completeness/overflow. The construction task stops before another action on any primed TNT or incomplete count. Native gates new TNT removal and placement, but does not block stop/cleanup/status or turn this tactical condition into UNKNOWN; existing move/look authority is not globally disabled, so a separately evaluated retreat is not structurally forbidden. This task implements no automatic retreat. A zero count is only a current local observation.

`latest_target_witness` reads one position from the most recent original v5 break/place request, only with matching current session/world/player/owner. It includes the original action ID and current loaded/state facts; it is not an arbitrary-coordinate reader. A changed or unloaded historical target does not block unrelated new observation tickets. Post-effect success requires original-ID matching current air/andesite, complete local primed count zero, and no observed unexpected local terrain destruction. `target_changed` alone is not proof of air. These observations are not a server-global atomic snapshot or future guarantee.

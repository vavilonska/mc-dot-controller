# Compact display-read cost and retained failures

Declared base: recovery TEST1, manifest SHA256 `073c5447c88863194ab5bc6edd1ab483dd815ac04e215d78eeb91ee006f45bf0`. This narrow delta does not include the later reconciliation, defensive-combat, external-stop or attached-rescue changes.

The first live TEST1 compact read, original request `TEST1_ORIGINAL_COMPACT_READ`, returned known read failure `compact_observation_terrain_incomplete`. Its result retained no page counts or timings. The old compact adapter called the full terrain export source, including light, block properties, fluid and collision callbacks, then rejected a continuation produced by the general 2 ms page budget. The evidence establishes that branch; it cannot establish the exact number of cells or elapsed time for the failed request.

The compact adapter now reads only loaded chunk block IDs. It checks the captured dimension's build-height bounds and caches at most the four intersected chunks; `getChunk(..., FULL, false)` cannot force missing chunks. It never invokes the full physics source, shape, light, fluid, property or block-entity getters. Missing/out-of-world/failed cells remain explicit unknowns as before.

A separate pure scheduling policy has a hard cell cap of 45 (radius 1) or 125 (radius 2) and an 8 ms cooperative ID-read budget. The existing 100 ms whole-callback budget, 64 KiB response bound, single callback/context/epoch checks and future-terrain rejection are unchanged. Partial coordinates or an exhausted scan still fail; no partial read is promoted to complete. A mod callback cannot safely be preempted, so overrun is detected and rejected after it returns. Success exposes the measured terrain read duration, in addition to the existing whole-callback duration.

Known compact failures retain a closed request-bound diagnostic: stage, radius, returned/total cells and scan/callback elapsed/budget nanoseconds. The actual HTTP transport validates its closed schema and exact original request/radius; invalid diagnostics are marked invalid rather than accepted as evidence. The Resident preserves read failures without stopping a gameplay owner. These diagnostics grant no execution, retry, settlement, physics, inventory-recovery or safety authority.

Offline validation includes full production compilation, injected-cost tests of the production scan scheduler across radius/height/negative-coordinate boundaries, partial/slow/failed/unloaded reads, unchanged production projection/clock guards, actual BridgeJson diagnostics, real loopback HTTP positive/negative diagnostic parsing, and the actual public owner chain with a modeled endpoint. The injected cost tests are not a measurement of Minecraft/LoadedSource latency. A fresh original read on the reviewed new paired artifact remains necessary to measure live latency. The failed TEST1 request is preserved and is not retried.

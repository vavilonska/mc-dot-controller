Scope: exactly one separately authorized NoAI batch and one original encounter
request. This plan does not authorize installation, authentication, a gate/launch
change, entity creation, live requests or any action now. The sole operator owns
all future setup and native GUI actions. Current tools are offline-only.

## Before any trial or active fixture

- Owner explicitly approves this concrete NoAI rehearsal and precise cleanup /
  pause / emergency rescue steps. There is one writer; old watchdog and other
  live automation stay stopped.
- Verify candidate version/JAR/controller/contract hashes, actual world, player,
  action/resident session, navigation origin and native release/idle/pending state.
- Use exactly two real registered adult NoAI zombies within the ordinary radius-8
  observation area, with stable positions and no other threats. Verify their exact
  UUID/native ID/type, per-UUID NoAI proof from the actual allowed evidence source,
  and full player health 20. Do not infer NoAI from lack of motion or copy test IDs.
- Operator confirms how independent CUA Escape reaches native PauseScreen and
  checks current screen/paused before any toggle. A paused picture is not a native
  input-release certificate. No automatic unpause is part of this tool.
- Register this one NoAI case in the queue-scoped ledger. Registration itself is
  not a native action or permission to spawn/modify entities.

## One request and strict stopping

The operator selects the one approved trial/stop variant. Run at most its original
registered request. A disabled gate, cold-budget refusal or other known admission
failure is evidence to retain, not a reason to enable anything, warm up, retry or
renew an action ID. NoAI cannot establish active-AI retreat effectiveness.

Any observed health decrease, invalid observation or missing window latches
STOPPED-SAFETY. Only a freshly proved original running owner can receive the
separate authorized single cancel. A visible terminal winner prevents sending it.
No trustworthy owner or unknown POST means independent operator Escape rescue,
then report; do not route around the lock or issue a speculative cleanup.

## Demonstrate narrow closeout

Only after the original full report proves known matching terminal or complete
explicit null admission, observed release and fresh idle identity:

1. Review the two registered UUIDs again in current complete local coverage.
2. Submit cleanup for the first exact UUID once. Preserve dispatch receipt and
   separate observed effect. Do not treat submitted:true as a kill.
3. Only after effect is established, repeat the separately authorized exact step
   for the second registered UUID. No selectors or broad kill are allowed.
4. Request native pause once, or record already-native-paused without toggling.
   Verify PauseScreen and paused together, plus independent input-release/idle
   observations. Raw-key direct takeover is not GUI lifecycle acceptance.
5. Seal the trial and separate cleanup evidence. Confirm old stop/intent files and
   controlled_trial_accepted=false were never changed. Finish with operator handoff.

This ordering uses inert verified NoAI fixtures so a failed cleanup can be safely
paused by the independent operator. If a separately chosen earlier pause leaves
kill submitted but unconfirmed, stop and report. Do not unpause, repeat kill or
continue with active AI. Any future bounded NoAI-only unpause observation needs a
separate concrete review and authorization, including no unknown cleanup receipt,
full health, no other threats and an explicit return-to-pause step. It is not an
API in this delivery.

## Stop outcomes and review criteria

- Unknown or failed main/cleanup/pause response: no retry; independent operator
  pause if needed and report the exact request/receipt/last proven state.
- UUID outside coverage, moved identity, truncated nearby, residual fixture or
  missing release: inconclusive; never infer removed or safe.
- NoAI closeout can be considered operationally demonstrated only from the actual
  original report, two precise effect observations, native final pause, unchanged
  locks and explicit operator handoff. It still does not establish combat, damage
  avoidance, survival, active AI, server-global absence or all optimization goals.
- Any next independent case is a separate decision after complete handoff; no
  automatic runner or cleanup-created combat permit exists. A new output uses the
  same ledger and cannot reset unresolved risk. No restart is required to request
  a properly authorized new NoAI case, and restarting is not an escape hatch.

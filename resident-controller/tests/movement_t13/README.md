# Offline movement-wire and full-reply regression

This suite exercises the production Python codec, Resident, queue, Runtime,
Toolbox service and serializer, and the production Node `ToolboxBridge` from
this checkout. Native input facts are **synthetic**, generated by the production
Java wire assembler/projection/serializer. It is not a Minecraft/world test and
provides no live movement or acceptance evidence.

## Run

First generate fresh fixtures with
`client-mod/validation/movement-t13/run.py`, using that runner's documented,
explicit local Java/compiler dependencies. Its output contains `wire-fixtures`.
Then, from the repository root, with Python and Node already installed:

```sh
python3 -B resident-controller/tests/movement_t13/run_offline.py \
  --fixtures /absolute/path/to/native-results/wire-fixtures \
  --output /absolute/path/to/new-python-wire-results
```

The fixture and output options also accept `MDC_MOVEMENT_WIRE_FIXTURES` and
`MDC_MOVEMENT_WIRE_E2E_OUTPUT`. Production source paths are derived from this
repository, never from the working directory or an external source override.
The output parent must exist, and the output must be new and outside the source
checkout. Existing results are never overwritten. No dependency installation,
network, credentials, live settings, game, or service startup is performed.

The finite runner starts only three owned test interpreter children, once each:

1. Eight Python contracts: seven movement-wire tests plus the existing
   read-only navigation-binding invariant.
2. Six full-chain Python tests, retaining complete queue/archive/reply evidence.
3. Thirty-eight Node boundary cases, using actual Python reply bytes in both
   whole and fragmented delivery, plus exact framing/request bounds.

Python test bodies block socket creation/connections and nested process
creation. Node test bodies block network entry points and child-process
creation before importing the production bridge. HTTP responses and the Node
child streams are in-memory doubles. The queue and archives are real local
files under the fresh output directory. The runner itself has bounded time,
log, and output storage; it only terminates children it created, and never
retries an unknown or failed phase automatically.

## Retained coverage

- Generated frames with 0, 3, 32, 64, 128 and 180 entity rows, complete cells,
  explicit null values, input immutability, and legacy inline representation
- Missing/unsupported markers, missing/dangling/cyclic/external references,
  authority chains, cross-owner/session/job/command/intent/frame mismatches,
  exact value types, changed entity frames/counts, and deleted cells
- Duplicate JSON keys rejected before dictionary collapse
- Original UTF-8 bytes versus decoded semantic siblings, including missing,
  changed, expanded or forged provenance and exact size/hash metadata
- Known 409 size diagnostics and a wholly synthetic definite refusal with no
  witness or retrospective diagnostic
- Native response, queue (2 MiB), archive (32 MiB), Python reply (1 MiB including
  newline), Node reply (1 MiB excluding newline) and Node request limits,
  including exact-boundary and +1 refusal cases
- No replay or added native request; original IDs, terminal cleanup and
  read-only public authority flags remain intact

The earlier historical-only T10 receipt assertion is not distributed here.
Its original evidence and coverage remain in the privately retained historical
validation packet. This portable suite contains no copied live T10 request,
receipt or setting; it replaces that assertion with an explicitly synthetic
refusal through the real transport and admission code. All protocol and
boundary negatives remain.

## Results and limits

`codec-report.json`, `python-report.json` and `node-report.json` contain test
results. `ORIGINAL-SEQUENCE-TERMINAL.json` records the original child exit
codes before postverification. `POSTVERIFY.json` verifies that source and
fixture bytes stayed unchanged, while `TERMINAL.json` records the aggregate
outcome. Source and input manifests plus logs preserve the exact run inputs.
A failed or interrupted run keeps its original evidence; use a distinct output
only after inspecting that terminal state and intentionally making a new run.

Passing means the real codecs/consumers handle these synthetic frames and
boundary conditions. It does not prove actual gameplay execution, world
geometry, collision behavior, server confirmation, or native action admission.

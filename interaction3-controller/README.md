# Explicit recovery_interaction_v3 controller

Run with `PYTHONPATH=interaction3-controller python -m interaction3_controller ...` from this paired source root. CLI flags/API are inherited in shape from v2: original `--ledger`, loopback `--endpoint`, explicitly selected existing `--token-env` or hidden prompt; new effects require `--plan` plus `--plan-sha256` and explicit normal-gameplay-risk acknowledgment. No new owner/ledger/token initializer. Local `report`, original-ID `status` and exact `stop` do not require a current PLAN. Credentials never belong in argv, logs, evidence or fixtures.

Only new effects on `recovery_interaction_v3` at `/control/recovery-interaction/v3/` are admitted. Schema_version stays1; the explicit profile changes the canonical request digest. All earlier short-input/v1/v2 requests, original-ID status/stop and terminal receipts use their unchanged stored-profile readers and routes. A new ID under an old effect profile is refused. Same ID means original payload/readback, never reissue. Shared ownership, ID namespace,256 count ceiling,8MiB byte ceiling, reply reserves and pre-effect atomic/fsync ledger remain unchanged. PENDING restart becomes persistent UNKNOWN; no profile, PLAN, world or owner replacement unlocks it.

This version does not widen the public local PLAN or action policy. PLAN loader and local policy are imported from the paired unchanged v2 module. Finite move≤8/no jump, bounded absolute look, slot-bound select and exact planned cobble/wart target break≤32 calls remain the only kinds. Native v3 challenge is1000ms/20ticks instead of old250ms/5ticks; absolute action ttl_ms remains counted from submit and is never renewed at first effect. CLI defaults look1000ms/break2000ms; request bound remains100..2000ms. The extra challenge budget is not a safety/gameplay guarantee or evidence of a successful live run. No automatic new-ID retry or candidate loop is part of this controller.

## Closed diagnostic extension

Only v3 status and observe add mandatory key `observation_refusal`. It is null without a recorded refusal, or exactly `{stage,age_ns,tick_delta,predicate_mask}`. Status stages are `admit`, `first_interaction_tick`, `first_input`; observe accepts only `observe`. Numeric age/tick are actual signed64 integer differences, never booleans/floats. Failed-prefix masks are0,1,3,7,15,31,63,127; passed bits in order mean nonnegative age, age≤1e9ns, nonnegative tick difference, tick difference≤20, player identity, level identity, XYZ tolerance, yaw/pitch tolerance. Numeric/mask contradictions are refused. Only admission source_missing/id_mismatch may use both numeric fields null with mask−1/−2 respectively. Mixed nulls, other negative masks,255, unknown stages and extra/missing fields are invalid.

A nonnull observe refusal requires an in-world, not-ready `observation_context_changed` response. A nonnull status refusal requires zero applied calls; first_input is move-only and first_interaction_tick nonmove-only. A known SETTLED `observation_stale_or_moved` terminal requires its diagnostic; UNKNOWN is not falsely rejected for missing diagnostic metadata. QUEUED/stop/UNKNOWN with diagnostic can legitimately arise between native updates and is not automatically rejected.

Diagnostics are evidence only: they do not relax request identity/digest, protocol terminal/release requirements, sticky UNKNOWN or retry rules. V3 persistence is native-owned; old records never acquire synthesized diagnostic fields. Raw receipt bodies are saved by the inherited ledger path before validation, unchanged except the existing transport secret-echo refusal guard.

## Offline verification

`PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=interaction3-controller python -m unittest discover -s interaction3-controller/tests -v`

Tests use temporary clones of the authorized actual97 ledger and original owner, in-memory transports and controlled temporary loopback fixture servers only; no game HTTP, real credential or native gameplay invocation. Each original record is compared by full deterministic encoding and original request/terminal reader; old UNKNOWN and PENDING, cross-profile ID collision/routing, PLAN, byte/count bounds, reserved stop/status space, fsync-before-POST, lost response and closed-history failures remain covered. Capacity projections are synthetic byte-volume estimates, not a promise that256 records fit. Production-codec fixtures and source/result hashes are indexed separately in `results/public/`; synthetic continuations do not assert live success.

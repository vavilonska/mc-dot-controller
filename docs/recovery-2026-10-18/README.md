# MDC Recovery 2.5：源码发布说明

版本：`1.1.8-recovery-test.2.5`。本次将已交付、已完成约定限定验收的源码保存到 GitHub `main`，保留先前工具箱文档和全部历史结论。源码公开保存不表示通用生产版、多人服或任意整合包已验证；使用范围仍是固定 Minecraft 1.21.1 / NeoForge 的独立普通单机测试副本。

## 本批能力与修复

- 清空主手/副手、显式光标恢复和完整菜单引用校验。
- 独立水桶落地救援守卫；同 owner 的原生 `follow_path` / `combat_entity` 可显式附加救援。
- 暂停时的精确 owner 清理、续租竞争处理、原任务 UNKNOWN 保留，以及摘要绑定的显式权限裁决。
- 托管步行的到达/取消与输入释放；盾牌使用窗口和有限后退。
- 排队取消遇到原动作刚结束时，保留“未分发 native cancel”的精确证明；不把整项转移升级为语义完成，不自动恢复光标。
- 显示用观测、无租约诊断、外部导航停止和存储 reserve/关闭诊断归档的配套源码与测试。

## 验收范围

这是逐版本记录，不是所有案例在 2.5 重新执行。完整机器可读摘要见 [ACCEPTANCE-SUMMARY.json](ACCEPTANCE-SUMMARY.json)。

- TEST1.2 / TEST2.1：受控垂直下落中的一次桶使用，关联单机服务端放水、桶变化和存活落地；TEST2.1 从空的已选槽自动切到水桶槽。
- TEST2.3：GUI 暂停与续租竞争后的原守卫终止、输入及租约释放；仍保留 needs_operator，不自动恢复。
- TEST2.4：同 owner 战斗的 12 次攻击后抢占与一次救援，原动作释放确认；精确摘要权限裁决后独立新读取成功。原任务状态、效果和清理 UNKNOWN 保留。
- TEST2.3：托管步行到达与另一次途中取消，设置恢复、两次 idle 采样、输入和 owner 释放。
- TEST2.1 / TEST2.3：1008 ms 盾牌窗口与 15 个 blocking 采样；后退增加间距 1.191 m，总移动 1.366 m，小于 2 m。零攻击、双方健康 20；未验证来袭伤害减免。

TEST2.5 最终另有正常保存后的服务端库存守恒证据。光标在关闭 GUI 前已由公共读取确认为空。后续冷保存证据不改写原生回执的 `server_confirmed:false`，历史失败和 UNKNOWN 也不被替换。本次 Git 保存没有启动游戏或新增实机验收。

## 使用与配对身份

入口见 [Recovery 调用指南](../../RECOVERY-TEST2-QUICKSTART.md)、[独立启动](../STANDALONE-BOOTSTRAP.md)和 [库存恢复](../INVENTORY-RECOVERY.md)。先调用 `mdc_catalog`，只使用当前真实返回的 session/context、能力版本和阻断原因；每个新动作使用新请求 ID。UNKNOWN 保留原 ID 与证据，不重复动作、不自动恢复，不把诊断读当作执行权限。

安装前正常关闭游戏和控制进程，保留原世界、旧版本和原 UNKNOWN 记录，成对更新源码运行时与 JAR。Python 禁止字节码写入；只加载固定的官方 Baritone API 1.11.3，不能同时加载 standalone 版本。托管步行拒绝附加落水保护，也不能与独立守卫争用 owner。

# Observation-driven End expedition

## Executable goal and boundaries

`expedition.end_expedition(runtime, job_id=..., boxes=1, ...)` is one bounded goal. It chooses targets, approach positions and local routes from fresh observations. The caller does not supply dragon/crystal/shulker UUIDs, cage bars, gateway positions or a rehearsed route. `deflect_shulker_bullet` is also a reusable exact-projectile defensive action. `expedition_status` returns historical checkpoint data only.

The expedition health floor is restricted to `12 <= min_health < 15`, and admission requires observed maximum health strictly greater than that floor plus five pearl damage. Impossible pearl-reserve settings fail before any mutation.

The starting point is an already authorized, focused, private singleplayer End world with a living dragon. This capability does not create a world, spawn entities, alter coordinates, connect a server, prepare credentials, issue chat commands or grant itself access. The code is an offline implementation candidate; no live dragon/gateway/outer-island/shulker acceptance is claimed.

## Concrete progression

1. Check actual inventory/effects/health. Equip an observed carved pumpkin through ordinary inventory operations. Require a bow and at least 32 arrows, a stone-or-better sword and pickaxe, a pearl, a carried crafting table, chests or actual compatible plank ingredients, supported full-cube building material and two free inventory slots. The entry minimum of 32 blocks is not a promise that 32 completes the expedition: each tower separately checks its entire ascent, firing bridge and return reserve. Carrying several stacks and durable tools is useful for the complete goal.
2. Discover currently loaded crystals and the living dragon within the explicitly bounded entity observation. Crystal absence at a station never establishes global clearance. Remember exact identities as historical candidates; mutation always re-observes the selected target.
3. Enumerate reachable, supported exterior columns from actual occupied geometry within eight horizontal blocks of the observed crystal, including offset columns around blocked tower fronts. Reserve the observed approach, up to 64 blocks of ascent, the exact outward bridge (at most twelve blocks), up to three cage bars, descent tool durability and action/time/walking return allowances under the original and enclosing scheduler budgets. Jump-place an ordinary pillar only through freshly observed clear headroom. At the top, inspect the actual cage and native-equivalent target-side bow trajectory; mine only reachable observed aperture bars and any iron-bar ray occluders, one fresh bar at a time. Plan the reserved endpoint at least 14.25 horizontal blocks from the crystal center to cover the ordinary 0.23-block radial arrival tolerance; verify actual clearance remains at least 14 before shooting. A known short-clearance refusal starts the reserved return without an extra bridge segment or shot retry. Newly observed obstruction or missing geometry starts the reserved return before another construction action. Native full-trajectory, blast, collateral and survival guards still govern the single shot. Stable loaded-area removal is required, followed by physical bridge retracing and one-level owned-pillar descent. See `CRYSTAL-ACCESS-PLANNER.md` for the exact bounded scope.
4. Dynamically approach the actually observed head in perched dragon phase 6 or 7. Strike with the ordinary held weapon and require later target health loss. Re-evaluate the phase/head between strikes. Only the same actual dragon's observed zero health plus this expedition's prior damage evidence unlocks gateway work. Missing/out-of-range dragons, entering the End, or a pre-existing dead dragon do not unlock it.
5. Discover a real loaded gateway block entity. Choose a close supported station derived from that gateway, generally three horizontal blocks away with eye level near the aperture. Reserve the ascent and return before tower construction. Before a throw, reserve the configured health floor plus five pearl damage; on ground, available food and observed natural regeneration may restore that reserve within 90 seconds. The native ordinary pearl action validates its loaded swept trajectory and aperture envelope. Success needs exact pearl consumption, the same dimension/context, stable supported landing, and an observed outer landing at least 512 horizontal blocks from the observed dragon-death position. A known released `dispatched:false` native rejection permits only the reserved return to base, never a rethrow. Unknown, missing receipts, or a dispatched shot without verified landing freeze the step.
6. Explore fresh loaded standable frontiers on the outer island. Recompute each short route; cross an observed adjacent empty cell only with a guarded physical bridge. Prefer observed shulkers, using actual line-of-sight and open-shell facts. Fight with the bow from 12–24 blocks so the shooter is outside the native eight-block unrelated-threat exclusion. Closed shells never admit a shot. Track an incoming bullet before another bow draw, then strike that exact observed projectile inside melee reach; verify its later local removal without player health loss. Elevated firing stations require the same reserve and owned-pillar return discipline. Levitation is a stop, never claimed safe flight or landing.
7. Prove actual shulker death with health evidence. Search for real shell item entities and approach them safely. Require actual stable inventory increases, continuing to other observed shulkers when a kill yields no shell. Previously carried shells do not count as newly acquired expedition material.
8. Use an observed reachable crafting table or place the carried table on a freshly observed supported cell. Craft missing chests from supported actual ingredients, then craft the requested shulker boxes through ordinary menu clicks. Completion needs the requested new shulker-box inventory delta and the complete dragon → gateway → outer landing → shulker death/material → crafting evidence chain.

## Safety, persistence and scope

- Native pumpkin checks remain active during End movement/placement/combat. Calm Endermen are not provoked by gaze; already aggressive or unknown-aggression Endermen stop the goal. Pumpkin protection does not exempt crystal blast or melee/ranged collateral.
- At a fully observed dry supported station with no nearby hostile/projectile/cloud exposure, the controller can eat actual inventory food and wait for two later health samples reaching the recovery target. New damage, a newly unsafe station, absent food or the original 90-second recovery deadline stops it. Resting on an owned tower also preserves the enclosing scheduler's return-time and action reserve. It does not eat while surrounded or lower the combat health floor.
- State uses a durable per-job checkpoint. Every composite step is persisted before submission, every native mutation reserves its budget first, and exact request IDs accumulate without resetting original counters or deadline. A process restart requires explicit idle-state revalidation; an interrupted/failed/unknown step is never replayed. Completed box inventory that later changes does not trigger automatic recrafting.
- Mutation helpers acquire local radius 4/vertical 4 terrain. Crystal cage planning additionally uses one fixed radius 8/vertical 4 read at the current top station, followed by fresh local mutation admission. A wider entity observation is separate from terrain coverage and is never called a complete world survey. Unknown or truncated safety evidence remains blocked.
- Raised stations reserve a return before ascent. The controller starts that return before its own or enclosing scheduler's action/deadline/distance reserve is exhausted. A no-shot gateway rejection retains its IDs and returns without retry. New damage, changed terrain/context, active hazards or uncertain action state may still prevent a safe return; such outcomes explicitly retain `risk_remaining:true`.
- Search is finite. No guarantee is made that an arbitrary outer landing has an accessible city inside the original budget, that city walls can be penetrated from a selected station, or that all shulkers/drop locations are reachable. Native ray/sweep/collateral failures are not bypassed. No elytra controller, dragon respawn ritual, universal structure search, arbitrary terrain excavation or complete Enderman combat is claimed.
- All completion evidence remains client-observed, with `server_confirmed:false`. Offline tests verify implementation and contracts, not real Minecraft survival or gameplay acceptance.

## Verification

`tests/test_end_expedition.py` covers observed frontier geometry, native-emitted aggression/gateway facts, load/identity and death gates, material/tool/return reservations, enclosing scheduler limits, restart and unknown latches, open-shell ranged policy, projectile priority, no-shot return handling, and exact crafting/material prerequisites. It also composes actual `Runtime` journal/correlation/freshness/independent-postsample machinery with synthetic endpoint responses for dragon health-to-death and projectile removal. Native loader/trajectory/placement tests are separate evidence. None are a live End completion run.

`tests/test_crystal_access_planner.py` adds complete serialized synthetic cylinder/cage worlds with radii 2–4 and varied heights, occupied former radius-three columns, offset access, real planner-selected bar lanes, unknown/obstructed geometry, original return reserves and mutation-free safety stops. These fixture worlds are not game exports or native gameplay evidence.

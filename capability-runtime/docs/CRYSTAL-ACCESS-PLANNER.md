# Bounded observed crystal access

The crystal planner no longer shares the gateway's four fixed radius-three base choices. It enumerates actual reachable route endpoints in the current complete, context-bound terrain slice, within eight horizontal blocks of the crystal and two lateral blocks of a cardinal outward lane. The route has at most sixteen edges. Loaded dry full-cube support, clear body and three-block ascent headroom are mandatory. Any already observed obstruction higher in that column also excludes it. Candidate ordering prefers the closest observed exterior column and then shorter access. No upper unknown slice is certified by this initial plan.

The selected plan stores target identity/position, observation request ID, original tick/context, approach route, base, height and exact outward firing endpoint. Height is bounded to 64 blocks above the base. The endpoint is the first cardinal cell with at least 14.25 blocks of centered horizontal crystal clearance, with at most twelve new bridge cells. The real `reach._arrived` predicate allows a 0.23-block radial horizontal error (not 0.23 on each axis); the additional 0.02 slack leaves every such arrival above fourteen blocks. Bases requiring a thirteenth segment are rejected, not extended. Budgets are derived from this chosen geometry, never reset or enlarged. Material and pickaxe durability retain the existing complete ascent/bridge/descent checks. Additional approach/cage action and time margins are checked against both goal and enclosing scheduler limits; bridge retracing is explicitly included in the return action/time reserve.

Each pillar ascent rechecks the current observed support, body and next headroom. Each outward bridge step checks current support plus the destination support-placement/body/head cells. Missing or changed geometry switches to the already reserved physical return before another construction action; it does not trigger excavation, a new route, teleportation or mutation replay. At the actual endpoint, fresh clearance is checked again: a known short-clearance refusal selects the original reserved return, without a shot, shot retry or additional bridge segment. Coasting and changed dynamic conditions are not certified by the margin; fresh observations and unchanged native admission remain authoritative. Descent and ground closeout require the original owned X/Z column, so lateral drift cannot mine a neighboring stack or clear the work. Unknown helper outcomes retain the existing durable inflight fence. Old crystal checkpoints without the new access plan cannot issue new approach/ascent/cage/bridge/shot actions; an existing physical return/descent remains bounded by its recorded state.

At the top, a fixed radius-eight/vertical-four observation inspects the cage. The planner uses the actual crystal bounding-box center and the native lower-angle full-draw bow model, including its 24 arc segments, for the target-side four-block aperture. Exact voxel-boundary supercover includes edge-adjacent cells. Non-air cells in that aperture must be observed iron bars within the existing cage distance bound. For offset columns, only actual cage bars occluding the eye-to-aperture-bar ray can additionally be selected. All selected bars combined, including already mined bars, are limited to three.

Before selecting a bar, the planner requires the observed interaction range, conservative center-ray clearance, dry known neighbors and a target whose neighbor shell fits the mining helper's radius-four observation. It also mirrors `resources.mine`'s observed falling/fluid-above predicate: sand, red sand, gravel, anvils and concrete powder above the selected bar are refused during read-only planning, permitting the existing reserved return. No dispatched or uncertain helper failure is caught as a safe replan. `dimensions.open_crystal_cage` is invoked for one bar; its resource helper and native adapter perform their own fresh admission. The aperture is observed again after every confirmed removal. No arbitrary terrain block is mined.

This target-side plan does not claim a clear distant bow corridor. The actual shot retains the native full loaded-trajectory, ray, range, collateral, blast and survival checks. A failed or unknown mutation is not a reason to retry. An inaccessible cage, unknown aperture, moved target or exhausted reserve yields an honest bounded failure/return rather than general tower excavation.

## Offline evidence

`tests/fixtures/crystal-tower-worlds.json.gz` contains every explicit cell in each declared box for three synthetic vanilla-shaped obsidian cylinders (radii two, three and four; tower tops Y72, Y78 and Y84), central bedrock and uncaged/caged variants. It includes complete air cells as serialized source data, not inferred missing-space defaults. `tests/fixtures/generate_crystal_worlds.py` reproduces these deterministic fixtures and does not launch Minecraft.

`tests/test_crystal_access_planner.py` loads those complete worlds and calls the production Python planner. It checks varying widths/heights, all old radius-three columns occupied, offset alternatives, actual cage/eye-ray selection, unknown and solid obstruction, observed reach, material/tool/inner/outer reserves, newly obstructed ascent/bridge return, and unchanged unknown-action fencing. Geometry-only post-removal fixtures explicitly edit a bar cell to air; they do not assign a success result to a mock action. These tests are not vanilla-generation, native input, survival, or live End completion evidence.

Post-review regressions preserve the exact accepted arrival `(14.3, 73, -1.5)` from the old radius-two plan and execute the real loaded mobility planner over serialized bridge supports for the reserved retreat, using a synthetic endpoint movement adapter. They also reject lateral descent/closeout drift and compare all falling-block-above cases against the actual resource helper. This is still offline path/semantic evidence, not native physics or gameplay.

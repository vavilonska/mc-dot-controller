# Bounded combat and delayed dimension contracts

This increment repairs existing capability contracts; it does not add a universal survival policy or claim live combat/End acceptance. The source baseline and completed noncombat cases remain separate immutable evidence.

## Combat reserve and feature agreement

`engage` carries the greater of the caller reserve and the native bounded-combat floor14 throughout the action. Single strike/defeat uses the existing species floor12 where required; blaze shield mode retains18. Higher caller reserves remain binding. Health must remain strictly above the applicable reserve. Default direct-strike duration is selected from the actual mode; explicit unsupported deadlines reject rather than being silently extended.

Fresh native state advertises `combat_capabilities` schema1, including the specific caller-health, encounter-route and shulker-open-shell guard versions. New Python paths fail closed if their native protection is missing; a registered API name or old cached info response is not support proof.

Hunt danger detection is separate from attack permission. The supported targets are not expanded. A scoped encounter-route binding applies the selected target identity (or no selected target during search), caller health, current danger and short-route safety checks at native callbacks. It does not alter default ordinary/noncombat navigation policy. Newly observed unsupported danger stops positioning rather than relying on a later attack refusal.

Shulker bow admission and drawing require current open-shell evidence, including the native raw peek value. An earlier positive animation or Python sample does not authorize release after closure. An interrupted draw preserves the existing uncertainty/release contract; stopping input is not automatically proof that no arrow was released.

## Delayed expected portal crossings

A transition permit is limited to one guarded `follow_path` and one supported source/destination pair. Its deadline is fixed when that original action is submitted and cannot move later when results or observations arrive. It is also bounded by the owner lease and128 post-observation frames.

Only a known successful action or the existing specifically recognized world-transition cancellation with exact native ID/session and confirmed release can create the permit. Safe same-source observations retain it and retain the next-mutation barrier. They do not count as crossing success. Expected destination observations must retain the exact player/native action identity, replace the ClientLevel generation, and remain on the same native integrated-server instance. The latter is a process-local UUID bound to the actual server object, not a save folder name supplied by a caller. Ordinary dimension changes retain it; disconnect/server replacement retires it. Missing, malformed or changed instance evidence blocks crossing.

Destination acceptance consumes the permit once. A second crossing, source-world replacement, other action, expired deadline or unrelated context cannot reuse it. Unknown outcomes never grant a permit. Restart still quarantines the durable owner; it does not restore or reissue a crossing action. Runtime requires later semantic destination samples and preserves its existing original-acquisition freshness fence.

## Evidence boundaries

Tests execute real Python Runtime/IntentClient/Watchdog/QueueClient/Resident and production Java parsers/guards where specified. Synthetic endpoint/menu/geometry effects are stated explicitly. Genuine-loader allocation tests do not simulate a whole real combat encounter. New live species/portal/crystal/dragon/shulker cases need independent labelled copies, current focused identities, exact equipment/site/budgets and their own semantic acceptance. The previous dry-flat32-block noncombat meter is not an arbitrary combat movement contract.
